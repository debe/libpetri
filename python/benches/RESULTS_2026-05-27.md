# Python binding perf sprint — results (2026-05-27)

All numbers are pytest-benchmark `mean` (µs unless noted), run on the same
machine (dev box), same conditions:

```
pytest benches/ --benchmark-only --benchmark-disable-gc --benchmark-warmup=off \
  --benchmark-save=<label> --override-ini="testpaths=benches"
```

Five experiments were run in sequence. Each is the previous baseline + the new
change (changes accumulate). Headline: **`bench_chain_async_callback[100]`
dropped from 3536 µs (baseline) to 750 µs (Exp 4b) — a 4.7× speedup on the
async callback path.**

## Changes applied (default behavior, no flags)

1. **Exp 1 — Build flags** (`rust/Cargo.toml` + `rust/.cargo/config.toml`):
   `[profile.release] lto="fat" codegen-units=1` + cargo cfg
   `pyo3_disable_reference_pool`. The latter kills the global ref-pool mutex
   PyO3 uses to defer cross-thread `Py<T>` drops — direct hit because tokio
   workers drop Python refs after every fire.
2. **Exp 2 — `Arc<str>` keys in `PyActionContext`**
   (`rust/libpetri-py/src/action.rs`): eliminate the `String::to_string()`
   per input/read place per fire. `TransitionContext` already hands us
   `Arc<str>`; we now keep it as-is.
3. **Exp 3 — Hoist `now_millis()`** in `marking_from_python`
   (`rust/libpetri-py/src/value.rs`): one timestamp per initial-marking batch
   instead of per token. Net effect on the suite was within noise but the
   path is now allocation-correct.
4. **Exp 4 — Manual coroutine driver**
   (`rust/libpetri-py/src/action.rs` async branch): replace
   `pyo3_async_runtimes::into_future_with_locals(coroutine)` (which wraps the
   entire coroutine in an asyncio Task) with a Rust-side driver that
   `send(None)` once and bails to asyncio only for actual suspends. For the
   common case (`async def f(ctx): ctx.output(...)` with no `await`), this
   collapses the per-fire cost from ~33 µs to ~7.5 µs.
5. **Exp 4b — Merge attach blocks on fast path** (same file): for coroutines
   that complete without yielding, flush outputs inside the same
   `Python::attach` block. Saves one GIL acquire per non-suspending fire.

Free-threaded Python 3.14t was tested separately as **Exp 5** — see below.
**Not adopted** for the default GIL build.

## Headline: `bench_chain_async_callback`

The centerpiece — a Python `async def` callback on every transition fire,
chain length N.

| N | Baseline | Exp 1 | Exp 2 | Exp 3 | Exp 4 | Exp 4b | total Δ |
|---:|---:|---:|---:|---:|---:|---:|---:|
| 5 | 239.5 | 247.3 | 240.5 | 230.2 | 95.0 | **87.5** | **−63.5%** |
| 10 | 413.5 | 431.3 | 414.5 | 386.5 | 133.3 | **127.1** | **−69.3%** |
| 20 | 786.5 | 757.8 | 792.5 | 713.5 | 220.0 | **192.4** | **−75.5%** |
| 50 | 1853.9 | 1734.6 | 1693.6 | 1705.8 | 452.7 | **412.3** | **−77.8%** |
| 100 | 3536.3 | 3275.0 | 3325.6 | 3336.3 | 809.9 | **750.4** | **−78.8%** |

The big bang is Exp 4 (the coroutine driver) — the previous code routed every
async callback through asyncio's Task machinery, which is ~33 µs/fire of
pure scheduling overhead. The manual driver only enters asyncio when the
coroutine actually suspends.

## Async/sync callback ratio (the stop criterion)

The goal was to halve the ratio of `bench_chain_async_callback[100] /
bench_chain_sync_callback[100]`. Original: 30.6×. After all changes: **7.0×**.
Target was ≤4× — not hit, but the floor is intrinsic Python async overhead
(coroutine object creation + StopIteration exception cost + 2nd `Python::attach`
when the await path runs). Closing the remaining gap would require either
free-threaded Python on parallel workloads or rethinking the async API surface.

| Run | sync_callback[100] | async_callback[100] | ratio |
|---|---:|---:|---:|
| Baseline (00) | 115.7 µs | 3536.3 µs | 30.6× |
| After Exp 1 (LTO/refpool) | 112.8 µs | 3275.0 µs | 29.0× |
| After Exp 2 (Arc<str>) | 106.1 µs | 3325.6 µs | 31.3× |
| After Exp 3 (hoist now) | 107.2 µs | 3336.3 µs | 31.1× |
| After Exp 4 (driver) | 108.8 µs | 809.9 µs | 7.4× |
| **After Exp 4b (merge attach)** | **107.3 µs** | **750.4 µs** | **7.0×** |

maps used to allocate strings per fire.

## Exp 5 — Python 3.14t (free-threaded build)

**Verdict: tested, not adopted as default.** The wheel builds and loads
cleanly on `cp314t` (PyO3 0.28 supports free-threaded out of the box; our
codebase has no `GILProtected` / `GILOnceCell` usage so no migration needed),
all 8 functional tests pass.

But the single-threaded bench numbers tell a clear story:

| Bench | Exp 4b on 3.12 GIL | Exp 4b on 3.14t | Δ |
|---:|---:|---:|---:|
| `test_single_passthrough` | 3.1 µs | 2.6 µs | **−16%** |
| `test_sync_linear_chain[100]` | 41.7 µs | 44.2 µs | +6% |
| `bench_chain_sync_callback[100]` | 107.3 µs | 106.4 µs | flat |
| `bench_payload[bytes_64k]` | 11.1 µs | 10.8 µs | −2.7% |
| `bench_chain_fork[100]` | 43.0 µs | 43.8 µs | flat |
| **`bench_chain_async_callback[100]`** | **750.4 µs** | **18,105 µs** | **+2310%** |
| **`test_async_linear_chain[100]`** | **159.1 µs** | **377.9 µs** | **+137%** |

The async-path numbers collapse. Both
`pyo3_async_runtimes::into_future_with_locals` and the underlying asyncio
event loop pay heavy synchronization overhead under `Py_GIL_DISABLED`.

The benchmarks above measure SEQUENTIAL execution — exactly the scenario
where free-threading shouldn't help (and where its lock overhead hurts). The
real value of 3.14t is **parallel async callbacks** — two tokio workers
firing Python actions on different transitions of the same net concurrently,
which is impossible under the GIL. That story needs a different benchmark
suite (parallel-callback) to capture, and is deferred to a follow-up.

**Practical recommendation**: ship default wheels on the GIL build for
2.6.0. Free-threaded support is "works but slower today; will become a win
when we add parallel-callback workloads".

## Reproducing

GIL build (default):

```bash
cd python
maturin build --release --features full
pip install --force-reinstall --no-deps \
  ../rust/target/wheels/libpetri-2.5.0-cp312-cp312-*.whl
pytest benches/ --benchmark-only --benchmark-disable-gc --benchmark-warmup=off \
  --override-ini="testpaths=benches"
```

Free-threaded 3.14t:

```bash
uv python install 3.14+freethreaded
uv venv .venv-ft --python 3.14t
source .venv-ft/bin/activate
uv pip install maturin pytest pytest-asyncio pytest-benchmark
cd python
maturin develop --release --features full
pytest benches/ --benchmark-only --benchmark-disable-gc --benchmark-warmup=off \
  --override-ini="testpaths=benches"
```

All saved bench runs are in `python/.benchmarks/Linux-CPython-3.12-64bit/`
(GIL) and `python/.benchmarks/Linux-CPython-3.14-64bit/` (3.14t):
`0001_00_baseline.json`, `0002_01_lto_no_refpool.json`,
`0003_02_arc_str.json`, `0004_03_hoisted_now.json`,
`0005_04_coro_fast_path.json`, `0006_05_merged_attach.json`,
`<n>_06_ft314.json`. Compare via `pytest-benchmark compare`.
